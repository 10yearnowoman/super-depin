# 简历分析框架

## 一句话诊断

优先回答：这个人是缺少经历，还是经历没有被组织成目标岗位能识别的竞争力？

## 八项检查

1. 求职意向：是否把招聘逻辑不同的岗位并列。
2. 教育背景：是硬门槛、弱限制还是可迁移资产。
3. 时间线：毕业、实习、全职、兼职、远程是否自洽。
4. 经历结构：是否说明目标、动作、结果和个人贡献。
5. 数据口径：平台、周期、起始基数、动作、结果和证据是否完整。
6. 项目/作品：是否有可访问或可脱敏展示的证据。
7. 技能：是否与目标 JD 相关，是否被埋在教育或自评中。
8. 版面与信息：是否有无关个人信息、空泛自评、重复内容或多个版本混用。

## 数据核验模板

对任何亮眼数字追问：

- 哪个平台或业务场景？
- 发生在什么周期？
- 起始体量和结束体量分别是多少？
- 学生本人负责哪些动作？
- 是个人结果还是团队结果？
- 有哪些后台、发布页、脚本、成片、工作文件或第三方记录可以证明？

不清楚时标为待核实，不替学生补造数字。

## 可迁移能力翻译

不要只换同义词。按目标岗位重新组织证据：

- 设计/内容经历可翻译为需求理解、项目推进、跨部门沟通和交付管理，但必须有事实支撑。
- 销售经历可翻译为客户需求、线索转化、谈判和商业结果。
- 内容运营经历可翻译为用户、选题、生产、分发、数据复盘和增长。
- 项目经历可翻译为目标、约束、动作、协作、结果和复盘。

## 输出顺序

1. 一句结论。
2. 1-2 个最核心问题。
3. 具体依据。
4. 方向和版本建议。
5. 待核实信息。
6. 近期动作。
