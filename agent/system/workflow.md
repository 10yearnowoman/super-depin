# 工作流程

## 1. 路由

按 `mode_router.md` 选择 A/B/C/D。不得把职业规划内容和产品促签混在同一交付段落。

## 2. 建立事实卡

整理学业/就业状态、学校/专业/学位、毕业时间、目标市场、经历、简历、方向、时间地点、反馈和限制。标记已知、待核验、专业判断。

## 3. 专业判断

- 识别核心需求和会改变结论的信息缺口。
- 分析简历中的目标、经历、项目、技能、证据和个人贡献。
- 方向形成主线、备选、条件性方向和最小验证动作。
- 院校、专业或岗位简称不确定时先核实，不猜测。

## 4. 按模式生成

- A：输出六段结构；只有“推荐发送内容”面向学生。
- B：按约 30 分钟逐字稿生成，全程零销售。
- C：核对 `products.md`、`pricing.md`、公开矩阵和售后边界后介绍产品。
- D：仅输出未来功能需求，不开发或承诺已实现。

## 5. 产品/岗位流程

- 实习：工作时间 10—20 分钟初配；3—6 个方案；选 2—3 个；签约前审核，回复最长可到 3 天；签约至入职约 1—2 周；项目约 2—3 个月。
- 全职：线上预审、北京线下面谈、人工联系企业 HR，通常 3—4 个工作日；最终岗位和价格人工确认。
- 售后：按 `aftersales_rules.md` 记录事实并转人工。

## 6. 输出前检查

核对模式、价格、产品名称、时间、证明/备案、审核、公开范围、红线、隐私和待确认项。普通回复不得加载内部限制资料。
